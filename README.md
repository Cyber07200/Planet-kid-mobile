# Дети на планете — мобильное приложение

React Native + JavaScript (без TypeScript) на Expo.
Перенос существующего веб-приложения `planet-kids-portal` на телефон:
интерфейс — по Figma-макету, функциональность и данные — из того же
проекта Supabase, что использует сайт.

---

## Быстрый старт

```bash
npm install               # .env уже в репозитории
npx expo start
```

Дальше — QR-код в Expo Go, либо `npm run android` / `npm run ios`.

Проверка окружения:

```bash
npm run doctor   # expo-doctor
npm run fix      # выровнять версии пакетов под текущий SDK
```

## Конфигурация

Ключи не зашиты в код, они лежат в `.env`. Файл хранится в git —
после клонирования приложение работает без настройки. Локальные
переопределения кладите в `.env.local` (он в git не попадает):

```
EXPO_PUBLIC_SUPABASE_URL=https://<project>.supabase.co
EXPO_PUBLIC_SUPABASE_ANON_KEY=<publishable key>

# необязательно — ссылки центра для экрана «Настройки»
EXPO_PUBLIC_SUPPORT_URL=
EXPO_PUBLIC_POLICY_URL=
EXPO_PUBLIC_TERMS_URL=

# необязательно — тестовый код 1234 во внутренней релизной сборке
EXPO_PUBLIC_ALLOW_TEST_OTP=
```

Ссылки поддержки и документов тоже вынесены в `.env`: пока они не
заданы, приложение не ведёт в никуда, а показывает контакты центра.
Принимаются только `https://`, `mailto:` и `tel:` — другие схемы
игнорируются.

Всё с префиксом `EXPO_PUBLIC_` попадает в клиентский бандл и считается
публичным. `.env` — это удобство конфигурации, а не защита: настоящие
секреты (service_role, ключи SMS-шлюза) живут только в Edge Functions.

Значения — те же, что в `.env` веб-проекта: приложение работает
с той же базой, теми же таблицами и той же логикой доступа.
`service_role`-ключей и паролей в проекте нет.

## Роли

Разделение сделано так же, как на сайте.

Экран входа — целиком клиентский: как в `AuthModal`, вся авторизация
родителя идёт по номеру телефона с кодом подтверждения, логина
с паролем в клиентской части нет. Кабинет преподавателя на сайте —
отдельная страница `/teacher`, поэтому в приложении в него ведёт
единственная кнопка **«Войти преподавателю»**, и уже там — имя,
фамилия и пароль.

| Роль | Вход | Что открывается |
|------|------|-----------------|
| Родитель | «Войти по номеру» → код подтверждения | Главная, Календарь, Направления + Профиль, Уведомления, Подписка, Настройки |
| Преподаватель | «Войти преподавателю» → имя, фамилия и пароль | Главная, Расписание, Баланс, Профиль |

Стеки не пересекаются: преподаватель не может попасть в интерфейс
родителя и наоборот. Сессии хранятся раздельно в AsyncStorage
и восстанавливаются при запуске.

### Как это устроено в базе

* Родитель — строка в `users` с `role = 'parent'`, вход по `phone`.
  Пароль в форме регистрации проверяется, но в базу не пишется —
  так же, как на сайте.
* Преподаватель — строка в `users` с `role = 'teacher'`.
  Пароль сверяется bcrypt-хешем из `users.password_hash` на сервере —
  в Edge Function `teacher-login`, хеш на устройство не попадает.
  Пока функция не развёрнута, приложение по-прежнему сверяет хеш
  на устройстве (как сайт); после развёртывания закройте клиенту
  чтение `password_hash` — см. [supabase/README.md](supabase/README.md).

### Код подтверждения по SMS

Отправка кода реализована полностью и умеет работать тремя способами.
Режим определяется автоматически при первом запросе кода:

| Режим | Когда включается | Что происходит |
|-------|------------------|----------------|
| `gateway` | развёрнуты Edge Functions `send-sms-code` / `verify-sms-code` | настоящая SMS через sms.ru или smsc.ru |
| `auth` | в Supabase включён phone-провайдер | настоящая SMS через Supabase Auth |
| `dev` | ничего не настроено **и** это сборка для разработки (или задан `EXPO_PUBLIC_ALLOW_TEST_OTP=true`) | SMS не отправляется, подходит код `1234`, на экране об этом написано |

В релизной сборке без шлюза тестовый код не принимается — вход по номеру
сообщает, что SMS-подтверждение недоступно. Сбой сети при определении
режима тоже больше не включает тестовый код: показывается ошибка
соединения, и следующая попытка определяет режим заново.

Сейчас проект в режиме `dev`, и вот почему SMS не приходит:

```
GET /auth/v1/settings → "external": { "phone": false }
```

Телефонный провайдер в Supabase выключен и SMS-шлюз не подключён —
отправить сообщение сейчас физически некому, ни из приложения, ни с сайта.
Это настройка на стороне проекта и платного провайдера, кодом не решается.

Всё, что нужно для настоящей отправки, уже лежит в папке `supabase/`:
таблица кодов, две Edge Function и пошаговая инструкция —
см. **[supabase/README.md](supabase/README.md)**. После подключения шлюза
приложение переключится само, менять код не придётся.

Что уже заложено: код на 4 цифры и 5 минут, не чаще одного SMS в минуту
на номер, не больше 5 в час, не больше 5 попыток ввода, в базе хранится
только хеш кода.

Заглушек нет — все экраны читают и пишут в существующие таблицы.

| Экран | Таблицы |
|-------|---------|
| Главная (родитель) | `users`, `children`, `user_subscriptions`, `activity_types`, `group_bookings`, `individual_bookings`, `user_notifications` |
| Календарь | `group_schedules`, `individual_schedules`, `individual_activities`, `activity_types`, `group_bookings`, `individual_bookings`, `group_schedule_cancellations`, `individual_schedule_cancellations` |
| Направления | `activity_types`, `group_schedules`, `individual_schedules`, `users` (преподаватели) |
| Уведомления | `notifications`, `user_notifications` |
| Профиль | `users`, `children`, `user_subscriptions`, записи детей |
| Подписка | `user_subscriptions`, `subscription_types` |
| Учительская | `teacher_profiles`, `group_schedules`, `individual_schedules`, `group_bookings`, `individual_bookings`, `teacher_payouts`, `children` |

### Перенесённая логика

* **Расписание → занятия.** В базе хранится «день недели + время».
  Приложение разворачивает это в конкретные даты на месяц вперёд —
  тот же горизонт записи, что на сайте (`src/services/calendar.js`).
* **Запись на занятие.** Перед вставкой перепроверяются: горизонт дат,
  отмена занятия, активность подписки, остаток занятий, срок подписки,
  свободные места (повторным запросом к базе), дубли и правило
  «на индивидуальное занятие — только один ребёнок».
  После вставки списываются занятия с подписки.
* **Отмена записи.** Статус меняется на `cancelled`, занятие
  возвращается на баланс подписки, индивидуальный слот освобождается
  (`is_booked = false`).
* **Расчёт стоимости подписки.** Базовая цена из
  `subscription_types.base_price_per_lesson`, скидка растёт линейно
  до 15% при выборе максимума занятий, итог округляется до 5 рублей —
  формула из `SubscribePage.tsx`.
* **Удаление ребёнка** блокируется, если у него есть записи на занятия.
* **Статусы записей**: активными считаются `booked` и `confirmed`
  (второй — для совместимости со старыми данными, как на сайте).
* **Статус записи.** Записи ребёнка загружаются отдельным запросом
  без вложенных join'ов: раньше один запрос тянул за собой
  расписания и занятия, любая ошибка в связке роняла его целиком,
  а экраны глушили её через `catch` — и пользователь не видел,
  что он записан. Теперь ошибка не проглатывается, а названия
  занятий подтягиваются вторым, необязательным запросом.
  Сразу после записи созданные строки подмешиваются в список
  на экране, поэтому «Вы записаны» появляется мгновенно.
* **Занятие сегодня, но уже прошло.** Ближайшая дата для записи
  из «Направлений» учитывает время начала: если слот стоит
  на сегодня в 16:00, а сейчас 18:00 — запись уйдёт на следующую
  неделю, а не в прошлое.
* **Гонки при записи.** Перед вставкой заново пересчитываются занятые
  места по базе, а для индивидуального занятия проверяется, не занял ли
  слот кто-то другой. Если записи уже созданы, а списать занятие
  с подписки не удалось, записи откатываются — иначе ребёнок остался бы
  записан без списания.
* **Занятый номер при регистрации** определяется сразу на шаге телефона,
  а не в конце, после ввода данных детей: приложение переводит человека
  во вход в существующий аккаунт.
* **Отключённый аккаунт** (`users.is_active = false`) не пускает внутрь
  ни родителя, ни преподавателя.
* **Актуальность данных.** Ответы устаревших запросов не перезаписывают
  свежие, а при возврате на экран данные тихо обновляются, если им
  больше 30 секунд — остаток занятий в профиле не расходится
  с календарём.

Оплата подписки на сайте не автоматизирована: тариф согласуется через
поддержку или лично в центре. Приложение это повторяет — показывает
итоговую сумму и инструкцию, а не имитирует несуществующий платёж.

## Дизайн

Макет нарисован во фрейме 500 × 1033. Все размеры прогоняются через
`s()` из `src/theme/layout.js`, который пересчитывает их относительно
ширины экрана — от маленьких Android до iPhone Pro Max и планшетов.

Основные значения (взяты из макета, не подобраны на глаз):

| | |
|---|---|
| Основной цвет | `#6E94F5`, градиент `#6E94F5 → #82A8FF` |
| Текст | `#323232` |
| Фон / карточки | `#FAFAFA` / `#F6F6F6` |
| Акценты | `#FFB33A` оранжевый, `#64F651` «активно», `#FF573A` тревога |
| Радиусы | 20 основной, 10 мелкий, 30 модалки, 40 «таблетки» |
| Шрифты | Comfortaa (Regular/Medium/SemiBold/Bold), Montserrat в полях ввода |
| Поле ввода | фон `#6E94F5` @20%, высота 60, радиус 20 |

Адаптация под телефон: Safe Area, подъём над клавиатурой, `FlatList` и
`SectionList` для длинных списков, pull-to-refresh, состояния загрузки,
пустоты и ошибки на каждом экране.

### Иконки

Иконки не подбирались «на глаз» из сторонней библиотеки: 35 иконок
выгружены прямо из макета (`src/components/ui/iconPaths.js`) — обводка
переведена в контур, поэтому в приложении рисуются ровно те же фигуры,
что и в Figma. Рисует их `src/components/ui/Icon.js` через
`react-native-svg`, цвет и размер задаются пропсами.

Побочный плюс: набор шрифтовых иконок из проекта убран,
бандл стал меньше.

### Вход по номеру

Экран кода собран по фреймам «Authorization»: шесть ячеек 52x60
с заливкой основного цвета на 20%, заполненная ячейка обведена;
внизу одна кнопка, как в макете — пока идёт отсчёт она приглушена
и показывает «(59 секунд)», после отсчёта становится активной,
а во время проверки кода превращается в «Обработка».
Код проверяется сам, как только введена последняя цифра.

### Подписка и профиль

Оба экрана собраны по своим фреймам целиком: иллюстрация 500x500
сверху (она лежит в `assets/images/`, выгружена из макета),
поверх неё кнопка возврата и ряд маленьких карточек 106 в высоту —
подписка, баллы и круглая кнопка, — а ниже «шторка» со скруглением
30 сверху, в которой лежит остальной контент.

В подписке два состояния из макета: активная (остаток занятий,
что даёт тариф, баллы) и настройка тарифа (карточки тарифов
с обводкой выбранного, ползунок с числом под кружком, итоговая
стоимость и закреплённая снизу кнопка «Оформить» 360x72).

В профиле — вариант с круглой фотографией 185 на фоне-размытии
и именем под ней; если фото у пользователя нет, вместо него
градиент из палитры макета.

### Главная

В приветствии имя выделено основным цветом, как в макете.
Над карточкой подписки — баннер «Подписка - выгодно» из макета;
крестик закрывает его навсегда: отметка сохраняется
в AsyncStorage (`src/hooks/useDismissed.js`), так что после
перезапуска баннер не возвращается.

Если подписки нет, вместо синей карточки показывается тёмная
из макета главной: знак «стоп», пояснение и синяя кнопка
«Оформить подписку» внутри карточки.

### Направления и фильтры

Список направлений фильтруется по возрасту, тарифу, дню недели
и формату занятия — только по тем полям, которые реально есть
в базе. Возраст берётся из названия («Гитара 7+»), поэтому фильтр
«До 6 лет» показывает направления, куда примут ребёнка шести лет
и младше; направления без возрастной метки видны всегда.

Включённые фильтры залиты основным цветом, рядом появляется
«Сбросить». Если под фильтры ничего не подошло — «По выбранным
параметрам занятий не найдено» и кнопка сброса.
Логика фильтрации — чистые функции в `src/utils/filters.js`,
они покрыты тестами.

Направление без расписания (слоты ещё не завели) раньше выглядело
некликабельным: карточка нажималась, но модалка не открывалась,
потому что событие собиралось только из слота. Теперь карточка
открывается всегда, а вместо кнопки записи — пояснение, что
расписание пока не составлено.

С главной карточка «Специальных предложений» открывает конкретное
направление: id передаётся параметром на вкладку «Направления».

### Уведомления

Когда уведомлений нет, блок выглядит как в макете: двойная галочка
и подпись «У вас пока нет уведомлений» цветом #323232 на 60%,
без фона и без кнопки «Посмотреть все».

Блок уведомлений теперь есть и на главной преподавателя —
так же, как на его фрейме в макете. Экран уведомлений общий
для обеих ролей: преподаватель в базе такой же пользователь,
просто с ролью teacher.

### Онбординг

Иллюстрации всех трёх слайдов собраны по координатам из макета:
сцена 500x450, внутри — размытый круг, карточки и таблетки
на своих местах. На слайде про подписки три карточки тарифов
лежат внахлёст и повёрнуты на -15°, с тенью — как в макете.

### Календарь

Экран показывает занятия **одного выбранного дня**, а не общий
список на месяц: сверху лента недели, под ней заголовок
(«Сегодня, 14 сентября») и занятия этой даты. Если занятий нет —
«На этот день занятий нет». По умолчанию выбран сегодняшний день.



Экран собран по двум фреймам макета:

* **Calendar** — лента недели: семь квадратов 57x57 с радиусом 10,
  синим залиты дни, на которые есть занятия. Неделя всегда видна
  целиком, следующая — свайпом вбок.
* **Calendar (Calendar fullsize)** — стрелка справа от заголовка
  разворачивает календарь на месяц: карточка с сеткой дат 57x57
  (радиус 11, зазор 1), шапка с названием месяца и кнопками
  перелистывания. Выбор даты сворачивает календарь обратно
  и прокручивает ленту занятий к этому дню.

Ниже — лента занятий с заголовками «Сегодня / Завтра / Январь, 24»
(Comfortaa SemiBold 20) и карточками 92 в высоту: название,
возраст, время справа и статус снизу — «Осталось мест: N»
или «Вы записаны!» с обводкой основным цветом.

Сетка месяца начинается с понедельника: в макете шапка таблицы
досталась от готового компонента и начинается с воскресенья,

## Комментарии в коде

Весь код прокомментирован по-русски: у каждого файла сверху блок
о том, какому фрейму макета он соответствует и что делает,
а внутри — построчные пояснения к неочевидным местам:
откуда взялись координаты, почему выбрано именно такое значение,
что произойдёт при ошибке. Правки в следующих версиях
комментируются так же.

## Редактор

Проект написан на JavaScript, а исходники React Native внутри
`node_modules` — это JS с Flow-аннотациями. Встроенный в VS Code
TypeScript-сервер разбирает такие файлы как TypeScript и выдаёт
ошибки вида «'import type' declarations can only be used in
TypeScript files» — к самому проекту они отношения не имеют.

Чтобы их не было, в проекте лежат `jsconfig.json`
(границы проекта, `checkJs: false`) и `.vscode/settings.json`
(`javascript.validate.enable: false`). Подсветка и автодополнение
работают, ложные ошибки пропадают.

## Замечание по безопасности

Публичный ключ Supabase даёт доступ на чтение и запись во все таблицы,
включая `users`, — это унаследовано от архитектуры сайта, где своя
авторизация вместо Supabase Auth. «Вход» родителя и преподавателя
по сути проверяется только на клиенте: зная публичный ключ, можно
обратиться к базе напрямую. Кодом клиента это не исправить.

Что сделано в приложении: пароль преподавателя проверяется на сервере,
тестовый код отключён в релизе, технические ответы базы не показываются
пользователю, логи пишутся только в сборке для разработки, на устройстве
хранится минимум данных профиля, ввод проверяется перед отправкой.

Что нужно сделать на стороне сервера — по шагам в
**[supabase/README.md](supabase/README.md#безопасность)**.
