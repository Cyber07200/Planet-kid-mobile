# Проверки логики

Все проверки работают с **настоящими файлами `src`**: загрузчик
(`setup.mjs` + `resolve-hooks.mjs`) дописывает расширения импортам,
как Metro, и подменяет только клиент Supabase базой в памяти
(`e2e/supabase.mjs` → `fake-supabase.mjs`). Копий модулей больше нет —
проверки не могут разойтись с кодом приложения.

Запуск (нужен только Node 20.6+):

```bash
node tests/all.mjs          # все наборы разом

node --import ./tests/setup.mjs tests/run.mjs          # чистая логика
node --import ./tests/setup.mjs tests/rules.mjs        # правила записи, ввод, ошибки
node --import ./tests/setup.mjs tests/e2e/run.mjs      # сквозной путь записи
node --import ./tests/setup.mjs tests/e2e/teacher.mjs  # «родитель записал → преподаватель видит»
node --import ./tests/setup.mjs tests/hooks/run.mjs    # настоящие хуки записи
node --import ./tests/setup.mjs tests/hooks/rls.mjs    # запись при закрытом чтении таблицы
```

Для проверок хуков один раз поставьте тестовый рендерер
(без изменения `package.json`):

```bash
npm install --no-save react-test-renderer@19.2.3
```

Без него `tests/all.mjs` просто пропускает проверки хуков.

## Что проверяет `run.mjs`

Даты и часовые пояса, разворачивание расписания в занятия, свободные
места, отменённые занятия, фильтры направлений, цена занятия в событии,
разделение обычных и разовых записей, тексты уведомлений.

## Что проверяет `rules.mjs`

Проверка ввода (имена, даты рождения, экранирование ILIKE, id),
тексты ошибок (технические ответы базы не показываются), правила записи,
сводка записей слота, слот направления и ближайшие занятия.

## Что проверяет `e2e/run.mjs`

`src/services/bookings.service.js` и
`src/services/notifications.service.js` на базе в памяти
(`fake-supabase.mjs`, поддерживает select/insert/update, eq/in/gte/lte,
single/maybeSingle и count). Проверяется весь путь записи:

- запись по подписке пишется с `subscription_id`, разовая — с `null`;
- в строку попадает именно выбранный `child_id`, а не только `user_id`;
- статус слота перечитывается перед вставкой;
- повторная запись ловится проверкой дублей по базе;
- свободные места считаются по базе;
- записи читаются обратно (то есть переживают перезагрузку экрана);
- отмена меняет `status` на `cancelled`, а не удаляет строку;
- отмена разовой записи не возвращает занятие на подписку;
- после отмены место освобождается и ребёнка можно записать снова;
- индивидуальный слот помечается `is_booked` и освобождается при отмене;
- уведомление создаётся в `notifications` + `user_notifications`;
- откат записи находит строку по слоту, даже если у записи только локальный id;
- при закрытом чтении таблицы возвращается локальная копия записи;
- отметить прочитанным можно только своё уведомление.

## Что проверяет `e2e/teacher.mjs`

Родитель пишет запись через `bookings.service.js`, преподаватель читает
её через `teacher.service.js` — обе роли работают с одними таблицами:

- преподаватель видит своё занятие в расписании (`group_schedules.teacher_id`);
- количество детей считается на конкретную дату (`bookingsByDate`);
- при открытии занятия виден именно записанный ребёнок, его возраст,
  родитель и пометка разовой записи;
- запись на другую дату не попадает в выбранный день;
- вторая запись увеличивает счётчик, отмена — уменьшает;
- свободные места считаются от реального числа записей.

## Что проверяет `hooks/run.mjs`

Здесь работает тот же код, что и в приложении: `useDirectionBooking` → `useBookingSheet` →
`useBooking` → `bookingFlow.js` → `bookings.service.js` → «база». Проверяется полный путь
нажатия «Записаться»:

- карточка направления открывается, единственный ребёнок отмечается сам;
- нажатие «Записаться» создаёт строку в `group_bookings`
  с правильными `child_id`, `user_id`, `schedule_id`, `lesson_date`;
- занятие списывается с подписки (`lessons_left`);
- создаётся уведомление в `notifications` + `user_notifications`;
- статус в интерфейсе меняется на «Вы записаны», мест становится меньше;
- повторная запись того же ребёнка не создаёт дубль;
- отмена открывает модальное окно проекта и меняет `status` на `cancelled`,
  возвращая занятие на баланс подписки.

## Что проверяет `hooks/rls.mjs`

Воспроизводит случай из логов, когда база отвечает пустой ошибкой
`{"message": ""}` на вспомогательные запросы (чтение `group_bookings`
закрыто политикой), а вставка разрешена. Запись обязана пройти:
строка создаётся, занятие списывается с подписки, пользователь видит
«Ребёнок успешно записан!», а не «Не удалось записаться».
